## 学习内容

### 一、AI 工作流工具 vs AI 框架

核心区别：
- **框架**（Spring AI / LangChain）：提供抽象层和扩展点，给开发者用
- **工具**（Claude Code CLI / JavaCliTool）：直接用 API + CLI，解决具体问题

你朋友的核心观点：
> "做 AI 工具为啥要用框架？两种方式：一个 API，一个 CLI。基于这两个能力包装技能和工具就好了。"

纵向领域限定：AI 工具应聚焦一个垂直领域（如代码审查、学习伴侣），不处理无关问题。

### 二、JavaCliTool 项目设计

项目地址：`D:\IdeaWorkSpace\JavaCliTool`

架构：纯 Java CLI 工具，无框架
- **Main.java** — picocli 命令行路由入口
- **Config.java** — 读取 config.properties 配置
- **LlmClient.java** — 封装 LLM API 调用（OkHttp + Gson，40行）
- **HandbookClient.java** — 从 HandBook 网站抓取章节内容
- **StudyCommand.java** — 学习伴侣工具（toc / quiz / summary 三个子命令）

核心设计思维：
- **API + CLI 两层**，没有 Spring Boot / IoC / 自动注入
- **代码做约束，不靠 Prompt 做约束**：章节路径存在性用 HTTP HEAD 预检，不是靠 LLM 去"判断"
- **工作流模式**：用户给目标 → 代码自动执行多步（校验→抓取→拼 Prompt→调 LLM→输出）

### 三、System Prompt vs User Prompt

| | System | User |
|--|--------|------|
| 作用 | 角色 + 行为准则 | 当前具体任务 |
| 变化 | 长期不变 | 每次不同 |
| 类比 | 岗位职责说明书 | 今天的任务单 |

区别的意义：逻辑清晰、可复用、符合 API 规范。

### 四、今天的关键认知

1. **框架思维 vs 工具思维**：框架让 LLM 规划流程，工具让代码掌控流程、LLM 只负责语义生成
2. **最小 AI 工具 = API 连接 + Prompt 工程**，不需要任何框架
3. **工具的工作流**：校验 → 数据获取 → Prompt 拼装（角色+规则+边界+数据）→ LLM 生成 → 输出
4. 靠 AI 不会退步，关键在于"代替思考"还是"加速思考"

## 学习问答

**问：工具和框架的区别是什么？**

答：框架（Spring AI/LangChain）是用来帮开发者搭建 AI 应用的基础设施；工具（JavaCliTool/Claude Code CLI）是直接用 API+CLI 解决具体问题的成品。框架需要别人写代码配置，工具装完就能用。

**问：System Prompt 和 User Prompt 为什么分开？**

答：System 设定长期角色和行为准则，User 传当前任务。分开后代码逻辑清晰、System 可复用，也符合 LLM API 的设计规范。

**问：工具的流程控制为什么要用代码做而不用 Prompt 做？**

答：代码约束是确定的（存在/不存在、通过/不通过），而 Prompt 约束是概率性的（LLM 可能不遵守）。关键路径用代码保证可靠性，LLM 只负责它最擅长的语义理解+生成部分。
