### 二、MCP（Model Context Protocol）

从 Handbook 拉取了 MCP 章节内容，MCP = AI 应用和外部工具的 **"USB 接口标准"**。

**四大核心概念：**

| 概念 | 说明 | 类比 |
|------|------|------|
| **Server** | 提供工具/资源的服务端 | USB 外设（打印机、U盘） |
| **Client** | 使用工具的 AI 应用端 | 操作系统（Windows/macOS） |
| **Tool Schema** | 工具的定义格式（参数+返回值） | USB 设备描述符 |
| **Permission** | 用户授权的访问控制 | 权限弹窗确认 |

**MCP vs Skill 的关系：**
- **MCP 管"工具怎么接"（协议层）** —— 定义了 AI 应用如何发现和调用外部工具
- **Skill 管"接了之后怎么用"（应用层）** —— 定义了用这些工具完成什么业务流程

用 Java 类比：MCP = JDBC（数据库连接协议），Skill = `OrderService` 类（业务流程编排）。两者不在一个抽象层上。

### 三、Skill（技能）概念

**Skill = 一个领域任务的"操作手册"，给 AI Agent 用。**

| 组成部分 | 作用 | 类比 |
|---------|------|------|
| **prompt** | 角色 + 行为准则 | 类的职责声明 |
| **plan** | 执行步骤/工作流 | 方法间的调用顺序 |
| **tools** | 允许使用的工具白名单 | 依赖注入的 bean |
| **rules** | 约束、坑点、边界 | 校验逻辑 + 异常处理 |

**存放位置：** `~/.hermes/skills/` 下，纯 markdown 文件（YAML frontmatter + Markdown body），按场景自动加载。

**跨 CLI 可移植性：**
- ✅ 知识本身（流程、规则、偏好）可移植
- ❌ 工具名和自动加载机制是 CLI 绑定的
- 其他 CLI 有各自的等效机制：Claude Code 的 `CLAUDE.md`、Codex 的 `CODEX.md`、Cursor 的 `.cursorrules`

### 四、回顾 LangChain vs LangGraph

| | LangChain | LangGraph |
|--|-----------|-----------|
| **流程** | 线性链，一步到底 | 带循环的图，可分支/回溯 |
| **适合** | 确定性的多步调用 | 需要自我检查+修正的场景 |
| **现实类比** | 工厂流水线 | 软件开发：写→测→改→再测 |

关键认知：**循环 = Agent 自我检查 → 发现错误 → 回头修正 → 直到正确。** Spring AI 属于线性链，要实现循环需手动写 for 循环 + Reflection 检查 + 重试。

### 五、Vibe Coding（氛围编程）

**Vibe Coding 不是 AI 理论，而是实践方法论/场景。** 描述"人怎么用 AI 来写代码"——人凭"感觉"判断代码对不对，不逐行读代码。Karpathy 命名 "Vibe" 的用意：你跟代码的关系从"每一行的主人"变成"验收者，感觉差不多就行"。

**Handbook 中 Vibe Coding 章节的 8 个知识节点：**

| # | 节点 | 难度 | 本质 |
|---|------|------|------|
| 1 | Vibe Coding | 初级 | 场景/方法论 |
| 2 | Claude Code / Codex CLI | 初级 | 开箱即用的产品工具 |
| 3 | Model / API Config | 中级 | 自管基础设施（模型、key、成本、权限） |
| 4 | GitHub / gh | 中级 | 版本控制是人的最后防线 |
| 5 | CLI / Script | 中级 | 一次性脚本工具，注意 dry run |
| 6 | Repo Workflow | 高级 | AI 也要走正常工程流程，不能跳过 |
| 7 | 在 AI×Web3 的位置 | - | 链上代码风险高，不能只靠 Agent |
| 8 | 最小实践 | - | 完整工程闭环练习 |

**讨论重点：**
- **Vibe Coding ≠ 不审查**。简单任务凭感觉，生产代码必须审慎
- **Node 2 vs Node 3**：Claude Code / Codex CLI 装上默认就能用；Model / API Config 需要自己管模型、key、streaming、成本（Hermes 属于后者）
- **Node 4 核心**：不是必须用 gh CLI，而是审查习惯不能省。你用 IDEA 看 diff 再手动 push 也是同样效果
- **Node 5** = JavaCliTool 这种一次性工具
- **Node 6 核心**：不要把 AI 当神仙，把它当新同事，该走的流程一个不能少
- 你朋友说的"多 LLM 分工协作"是"多个 AI 角色一起干活"，Node 6 是"干完活怎么合规上线"，两者不冲突

## 学习问答

**Q: MCP 和 Skill 是什么关系？**
A: MCP 管协议层（工具怎么接），Skill 管应用层（接了怎么用）。MCP = JDBC，Skill = Service 类。

**Q: Skill 能跨 CLI 移植吗？**
A: 知识可以（纯 markdown 任何 LLM 能读），但工具名和自动加载机制不能。需要翻译成目标 CLI 的格式（CLAUDE.md / CODEX.md / .cursorrules）。

**Q: LangChain 和 LangGraph 的本质区别？**
A: LangChain 是线性链（确定性的多步调用），LangGraph 是带循环的图（不确定性场景，LLM 自检→修正→直到正确）。

**Q: Vibe Coding 是 AI 理论吗？**
A: 不是。它是实践方法论/场景，描述"人怎么用 AI 来写代码"。前面 LLM / Prompt / Context 等是 AI 理论，Vibe Coding 是落地篇。
