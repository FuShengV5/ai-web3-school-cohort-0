### 学习内容

- **Handbook 章节**：向量知识库（RAG）分级架构（独立讨论，非 Handbook 正式章节）
- **关键概念**：
  - **向量知识库 Level 0**：规则硬切分块 → Embedding API → 向量存储 → 余弦相似度检索 → Top-k → LLM 回答。适用 Demo，极限在几百个 chunk
  - **向量知识库 Level 1（分水岭：从"能搜"到"搜得好"）**：语义分块（句向量相似度骤降处切分）→ 混合检索（向量 + BM25 关键词精确匹配）→ Reranker（交叉编码器精排 30→top-3）→ Golden Set + Harness 闭环评估。Reranker ≠ LLM 判断：Reranker 做相关度打分，LLM 做信息充足度判断，两者不可替代
  - **向量知识库 Level 2（用户提问端优化）**：查询改写（LLM 优化模糊问题）、多查询分解（拆多个意图分别搜）、Agent 式检索（LLM 分析 top-3 后决定是否改写重搜）、文档解析流水线（PDF/表格/OCR）、多租户隔离
  - **Reranker 定位**：是"守门员"而非"教练"——向量+BM25 粗召回 30 条 → Reranker 精排 top-3 → LLM 判断信息够不够。LLM 只看精排后的 top-3，不看粗召回 30 条（防止噪声干扰 + 节省 token）
  - **Skill 本质**：场景对应的操作手册，封装领域专知和流程规范，而非"角色身份"。角色互斥（司机/厨师），Skill 可叠加（同时加载 PR 工作流 + SQL 审查 + 调试 skill）。类比 Java：角色 ≈ 类继承，Skill ≈ 接口多实现
  - **Agent 工作流退化**：日志格式偏离的原因是 agent 长期使用后逐步省略了"加载模板"步骤，非模型幻觉。deepseek-v4-flash 对复杂格式约束保持力比完整版弱，但主因是 agent 工作流退化
