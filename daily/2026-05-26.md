## 学习内容

### 一、LLM / Agent / Framework 的关系

| 组件 | 类比 | 说明 |
|------|------|------|
| **LLM** | 🧠 大脑 | 语义理解、推理、生成 |
| **Agent** | 🏃 完整的人 | LLM + 工具 + 规划 + 循环 |
| **Framework** | 🏗️ 骨架 | 把大脑装进去、链接感官和手脚的框架 |

Hermes 的特殊性：既是 Agent 产品（安装即用，不需要写代码），也是可扩展的框架（支持自定义 Tool / Skill / MCP）。

### 二、Claude Code / OpenCode / Codex 不是框架

它们是 **Agent 产品**，不是框架：
- 框架（LangChain / Spring AI）：需要你写代码配置才能跑起一个 Agent
- 产品（Claude Code CLI）：`npm i` 安装完直接用，内部已经封装了完整的 Agent 循环

### 三、LangChain vs LangGraph 核心区别

| | LangChain | LangGraph |
|--|-----------|-----------|
| **流程** | 线性链，一步到底 | 带循环的图，可分支/回溯 |
| **适合** | 确定性的多步调用 | 需要自我检查+修正的场景 |
| **现实类比** | 工厂流水线 | 软件开发：写→测→改→再测 |

**关键认知：**
- Spring AI 属于线性链（类似 LangChain），不是 LangGraph
- 成绩环比例子（查当月→查上月→算环比）是**线性多步**，不是循环

### 四、循环的本质

**循环 = Agent 发现自己错了 → 回头重新来 → 直到正确。**

用 OpenCode 的例子：写代码→编译→报错→回去改代码→再编译→通过→返回。

Spring AI 要实现这种循环，需要在 Service 层手动写 for 循环 + Reflection 检查 + 重试逻辑。LangGraph 把这种模式封装成了框架的一等公民。

### 五、各框架定位

| 框架 | 一句话定位 | Java 生态 |
|------|-----------|-----------|
| **LangChain** | 线性链编排，生态最全 | LangChain4J |
| **LangGraph** | 带循环的图编排 | LangChain4J 有不成熟版 |
| **OpenAI Agents SDK** | 轻量 Agent，绑定 OpenAI | 无 |
| **DSPy** | 自动优化 Prompt | 无 |
| **Spring AI** | Spring 官方，无缝整合 Spring Boot | ✅ 你在用 |
| **Hermes** | 端到端 Agent 框架+产品 | 无 |

## 学习问答

**问：Framework 可以理解为 Agent 的身体吗？**

答：不准确。Framework 更像骨架（骨骼+神经系统），Agent 才是完整的人（骨架+大脑+感官+手脚）。

**问：Spring AI 跟 LangChain4J 有什么区别？**

答：做同一件事的两套实现。Spring AI 是 Spring 官方出品，Spring Boot 无缝整合；LangChain4J 是社区移植 Python LangChain。你已经在用 Spring AI 了，没必要换。

**问：Function Calling 和 LangChain 是什么关系？**

答：Function Calling 是 LLM API 的一个底层能力（返回工具调用格式），LangChain / Spring AI 都是封装了这个能力的上层框架。

**问：用 Spring AI 怎么实现循环？**

答：手动在 Service 层写 for 循环：调 LLM → Reflection 检查 → 没通过就加上反馈重新调 LLM → 最多尝试 N 次。
