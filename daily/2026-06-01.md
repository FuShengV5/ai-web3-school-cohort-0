### 学习内容

- **Handbook 章节**：评估（Evaluation）
- **关键概念**：
  - **Golden Set**：人工抽样的多维度测试样本集，每条样本包含输入 + 期望行为（必须包含的信息、必须拒绝的情况），不是评分标准本身。评分标准是每条样本自带的期望约束
  - **LLM-as-Judge**：用模型给输出评分，配合规则 grader（可自动判断的字段先走规则）。不神化 Judge，高风险样本保留人工抽检
  - **Regression**：每修一个 bug 就加入 Golden Set，防止"修 A 坏 B"，每次改动重新跑
  - **Observability**：线上日志/追踪，发现真实用户失败场景，反哺补进 Golden Set
  - **Harness**：eval 编排框架，6 个最小要素（输入样本、期望输出、被测系统版本、模型配置、运行日志、结果报告）。价值在**可重复**。类比 Java：Harness ≈ JUnit，Golden Set ≈ 测试用例，LLM Judge ≈ AssertJ
- **代码 / 实验**：无，概念学习
- **Fine-tuning 概念补充**：
  - 微调前提：通过 Harness + Golden Set 确认问题稳定存在，且依次排除 prompt / RAG / Schema 等非微调方案后仍残留，才进入微调
  - **排查链**：改 prompt → 加 RAG/Few-shot → 优化检索+输出格式 → 仍有残留 → 进入微调
  - 微调 = 给正确答案做示范，不是"改错题"——assistant 回答需人工重写
  - 数据集格式：JSONL，每行一条完整对话 [system + user + assistant]
  - 训练集（80%）：给模型学，调权重；验证集（20%）：藏起来只测不学，防 Overfitting。类比：教科书例题 vs 期末考试
  - 云端微调流程：准备数据集 → 分训练/验证文件 → 上传 → 发起训练任务 → 等完成 → 拿到专属模型 ID → 正常调 API 使用
  - 微调是阶段性的（训练一次用无数次），不是每次调用都训练
  - 同领域场景可合并到一个数据集训练一个模型，输出格式/风格差异大时才需要分开训练
